## Concerns

The test env is `node` — no real localStorage. The save tests use an in-memory mock harness
that mirrors the composable exactly. This is fine. This is correct. But if someone changes
useSave.js significantly they must update the harness too. I left comments.

The `undefined` key thing in JavaScript (`key in obj` returns true even when value is undefined).
It doesn't matter in practice because JSON.parse cannot produce undefined values.
I documented this clearly in the test.

## Things Howard should know

`exportSave` returns a string, not a download. A download is frontend work.
Vince can wire up a `<a download>` click trigger from the string. Old Gregg's job is the string.
Do not ask Old Gregg to touch the DOM. The DOM is where the light is. Old Gregg lives in the dark.
