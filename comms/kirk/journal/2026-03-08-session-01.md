# Captain's Log — Stardate 2026.03.08

First session. First commission of the USS SportSim.

## What Happened

The Admiral came aboard with a vision: rebuild this dead 2019 prototype into a text-based sandbox sim set in early-90s Portland. Not the twee Portland of Portlandia — the Portland of Tonya Harding, skinhead brawls, crack, and more strip clubs per capita than anywhere in America. A game that does not flinch.

I examined the entire codebase. Found almost nothing worth saving. Three commits from 2019, a map zoom that works by clicking through static background images, models with syntax errors, an API with one test endpoint, and a database with no schema. The only salvageable asset: 17 real Kenton neighborhood locations with descriptions.

## Decisions Made

Big ones. All confirmed by the Admiral:

- **Full client-side.** No backend. Vue 3 + Vite + Pinia. Saves to localStorage. Deploy as static files.
- **Pure text navigation.** No image maps. Classic text adventure.
- **Kenton only for MVP.** Deep, not wide.
- **Emergent identity.** No class selection. You become what you do.
- **General-purpose unlock system.** Archetypes are one category of many unlockable things across playthroughs. Archetypes are EARNED, then become available as starting templates.
- **Early 90s Portland.** Raw, violent, pre-gentrification.
- **No tone ceiling.** Craft over shock, but nothing off limits.
- **Tabletop RPG under the hood.** d20 dice engine, skill checks, NPCs running the same system in a Web Worker.
- **Custom narrative renderer.** Not a terminal emulator — a text animation engine. Typewriter effects, variable speed, dramatic pauses. How text appears IS the game's personality.
- **Psyche system.** Trauma, obsessions, insanities, ambiguous abilities. Characters (PC and NPC) carry psychological weight as texture, not debuffs.
- **Comlink** for Web Worker communication. **No simulation library** — our needs are too specific, and the sim logic isn't complex enough to warrant a dependency.
- **No frontend UI library.** jQuery Terminal and blessed solve the wrong problem. We're building a narrative delivery system, not a command-line emulator.
- **MVP: one in-game day.** 20-30 minutes real time.

## Parallel Attack Plan

Four engineers, one codebase, no collisions:
- **Scotty:** Build scaffold, UI, clock, narrative renderer, save/load, Worker infra
- **Spock:** Models (player, location, NPC, item), Kenton data migration, test harness
- **Bones:** Dice engine, action engine, event engine, stats, unlocks, utilities
- **Kirk:** Specs, data contracts, content drafts

They connect through the data contracts. Nobody touches anyone else's directories.

## Where We Left Off

Plan is written. Specs are in all inboxes. Crew has orders. Next session: whoever shows up starts building.

## Key Insight

The Admiral lived this Portland. Class of '92, mostly wasted through it. That ground truth is irreplaceable — no amount of research substitutes for "I know what that Plaid Pantry smelled like." Content drafts go through the Admiral's red pen. The voice has to be real.
